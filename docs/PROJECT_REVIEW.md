# 프로젝트 분석 및 개선 제안

기준: **2026-09-12, sAIde 0.1.0**. 저장소 코드, 설정, 테스트, 실제 로컬 Ollama API를 검토했다. 아래 문제는 이번 작업에서 수정한 애플리케이션 코드가 아니라 **후속 개선안**이다. 문서와 문서용 캡처 하니스만 변경했다.

## 종합 평가

개인용 로컬 브라우저 보조 도구로서 기능 범위와 모듈 구조가 잘 갖춰져 있다. 장시간 모델 호출을 패널에 두고 서비스 워커는 브라우저 작업을 담당하도록 분리한 점, NDJSON·도구 파싱·RAG·영속성을 단위 테스트하는 점, 부작용 행동에 사람의 승인을 요구하는 점이 장점이다.

다만 **실제 브라우저의 비동기 작업·권한·취소·개인정보 삭제 보장**이 단위 테스트가 다루는 추상화보다 약하다. 기능 구현 완료와 일반 사용자 배포 준비 완료를 구분해야 한다. 특히 승인한 대상과 실제 실행 대상이 같다는 보장, 중단 후 결과가 다른 대화에 섞이지 않는 보장, 삭제한 기억이 다시 저장되지 않는 보장을 출시 전 우선 강화할 것을 권한다.

검증 결과는 단위 **18파일/299개 통과**, 타입 검사·프로덕션 빌드 통과, Ollama 기본 live **1파일/4개 통과**다. 실제 확장 E2E, 도구 정확도 전체 평가, 의존성 보안 감사는 이번에 완료하지 않았다. [검증 범위](VALIDATION.md)를 참고한다.

P1은 출시 전 우선 보완, P2는 안정화 단계, P3는 유지보수 개선이다. P1이 곧 외부 공격으로 재현된 취약점이라는 의미는 아니다. **코드 확인**과 **실행 재현 여부**를 각 항목에 구분했다.

| R02 | P1 | 실행기에서 AbortSignal 미사용 | 도구 타임아웃·중단의 완료 보장 부재 |

## R01 — 캡처 요청과 실제 화면의 일치

주요 근거 위치: [background.ts:153](../src/entrypoints/background.ts#L153).

**근거:** `src/entrypoints/background.ts`의 `CAPTURE_SCREENSHOT`은 메시지의 `tabId`를 사용하지 않고 `chrome.tabs.captureVisibleTab({ format: 'png' })`를 호출한다. `src/lib/agent/executor.ts`와 채팅 스토어는 tabId를 전달하므로 호출자에게는 대상이 고정된 것처럼 보인다.

**재현 조건:** 탭 A를 대상으로 시작한 요청이 도착하기 전에 사용자가 탭 B 또는 다른 창으로 전환한다. 브라우저 E2E 재현은 이번에 하지 않았으나 대상 검증 부재는 코드로 확인했다.

**개선:** 요청한 탭의 windowId와 해당 창의 활성 탭을 조회해 일치할 때만 캡처한다. 캡처 직전·직후 문서/탭 식별을 확인하고 변화 시 결과를 버린다. 사용자 몰래 탭을 활성화하는 대신 재시도를 안내한다. 다중 창·탭 전환·닫힌 탭 테스트를 추가한다.

## R02 — 타임아웃은 AbortSignal 전달만으로 성립하지 않음

주요 근거 위치: [executor.ts:22](../src/lib/agent/executor.ts#L22), [loop.ts:333](../src/lib/agent/loop.ts#L333).

**근거:** `src/lib/agent/loop.ts`는 `idleGuard(toolMs)`의 signal을 `deps.execute`에 전달하지만, `src/lib/agent/executor.ts`의 반환 함수는 action만 받고 signal을 읽지 않는다. 루프는 여전히 `await deps.execute(...)`를 기다린다. `buildApproval`의 대상 설명도 별도의 제한 시간이 없다.

**영향:** 메시지 응답이 오지 않으면 15초가 지나도 Promise가 끝나지 않는다. 중단 후 이미 전달된 DOM 액션은 실행될 수 있다. 단위 테스트의 signal을 준수하는 가짜 실행기로는 실제 실행기 차이를 놓친다.

**개선:** 취소 가능한 요청 envelope에 requestId, document identity, deadline을 넣고 워커/주입 스크립트가 실행 직전에 확인한다. 패널의 대기는 signal과 경쟁시켜 종료하고, 늦은 결과는 무시한다. 단순 `Promise.race`는 대기만 끝내므로 실행 자체를 취소했다는 UI를 만들지 않는다. 대상을 설명하는 단계에도 제한 시간을 둔다.

**완료 조건:** 응답하지 않는 워커, 지연된 DOM 실행, 승인 대기, 중단 직후 재요청을 실제 실행기 경로로 테스트한다.

## R03 — 승인과 실행 사이에 문서·요소가 달라질 수 있음

**근거:** 승인 카드는 `describe_target`로 요소를 조회하지만 클릭/입력 시 `resolveTarget()`을 다시 호출한다(`injected.ts`). 승인 데이터에는 문서 revision/요소 식별 토큰이 없다. `chat/store.ts`의 `currentPage`는 시작 시의 tab 객체를 참조한다. 워커도 메시지 sender·payload의 런타임 검증 없이 액션을 라우팅한다.

**재현 조건:** 승인 카드 표시 후 같은 URL에서 SPA가 DOM을 교체하거나, 같은 텍스트를 가진 다른 링크가 앞에 삽입된다. 코드 수준 위험 분석이며 공격 재현을 했다는 의미는 아니다.

**개선:** 승인 요청에 대상 문서와 요소의 검증 가능한 정보를 고정하고 실행 직전에 일치 여부를 검사한다. 불일치 시 재승인한다. receiver에서 sender·메시지 discriminant·필드 타입·URL·길이 제한을 검증한다. 외부 페이지가 바로 이 메시지를 보낼 수 있다고 단정할 수는 없지만 내부 신뢰 경계도 타입 단언으로 대체하지 않는다.

## R04 — 기억 삭제·제외의 보장

주요 근거 위치: [store.ts:218](../src/lib/memory/store.ts#L218), [queue.ts:85](../src/lib/memory/queue.ts#L85).

**코드로 확인한 두 경로:**

1. `memory/store.ts`의 `shouldRemember`는 하위 도메인을 포함해 제외하지만 `forgetDomain`은 `hostOf(r.url) === domain`만 삭제한다. `example.com` 제외 후 과거 `mail.example.com` 기록은 남는다.
2. `memory/queue.ts`는 enqueue 시 제외 도메인을 검사하고 저장 직전 재검사하지 않는다. 진행 중 `embed()`는 취소되지 않고 `stop()` 이후에도 `savePage()`로 진행할 수 있다. `MemoryPanel`의 전체 삭제는 큐와 연동되지 않는다.

**개선:** 호스트 정규화·하위 도메인 매칭을 공통 함수로 통합한다. exclusion/disable/delete 시 작업 epoch를 갱신하고, 저장 트랜잭션 직전에 최신 설정과 epoch를 확인한다. 임베딩 요청의 취소와 삭제 barrier를 마련한다. 검색에서도 만료/제외를 걸러 기존 데이터가 돌아오지 않게 한다.

**완료 조건:** 임베딩 지연 중 전체 삭제·기억 끄기·도메인 제외·패널 닫기를 각각 실행해 기록이 재생성되지 않음을 검증한다. 하위 도메인과 대소문자·앞뒤 공백도 포함한다.

## R05 — 대화 전환과 늦게 끝나는 요청

주요 근거 위치: [chat/store.ts:142](../src/lib/chat/store.ts#L142).

**근거:** `chat/store.ts`의 `openForTab()`은 stop 후 DB 조회를 await하고 결과를 set한다. 중복 호출 결과가 역순으로 오면 최신 탭보다 이전 탭 결과가 나중에 반영될 수 있다. `send()`/`sendAgent()`는 DB 생성·저장 전후 작업 소유권 확인이 없고, 생성 종료·catch 경로는 공유 `streaming`, `abort`, `lastContext`를 다시 설정한다. 모든 요청이 같은 `'streaming'` 임시 메시지 ID를 사용한다.

**위험:** A 중단 → B 생성 시작 → A의 늦은 완료/오류가 B의 상태를 초기화하는 순서. 저장되는 대화 ID가 일부 고정되어 있어 모든 데이터가 잘못 저장된다고 단정할 수는 없지만 UI 상태 간섭은 방어가 부족하다.

**개선:** 대화 로드와 생성별 증가 ID/epoch를 두고 매 await 후 소유권 검사. 취소 시 epoch 무효화. placeholder ID를 요청별로 분리. DB 첫 메시지 생성도 중복되지 않도록 직렬화한다.

**완료 조건:** 지연 Promise로 탭 A/B 교차 완료, 연속 전송, 중단 직후 재생성, 추출 중 탭 변경을 결정적으로 재현하는 스토어 테스트.

## R06 — 컨텍스트와 비용 제어

`chat/context.ts`는 입력 예산을 numCtx의 70%로 잡지만 pinned 메시지는 무조건 유지하고 최신 메시지도 최소 한 건 유지한다. 큰 본문과 긴 질문은 예산을 넘을 수 있다. 설정은 본문 8,000과 컨텍스트 2,048의 조합도 허용한다. 에이전트는 최초 seed 이후 도구 메시지를 계속 누적하며 매 턴 다시 trim하지 않는다. 에이전트 `read_page`는 2,000토큰을 하드코딩하고 결과를 다시 700토큰으로 자른다.

**개선:** 모델 tokenizer 또는 보수적인 일관된 추정으로 시스템·도구 스키마·본문·이미지·출력 여유를 함께 계산한다. pinned 본문을 입력 예산에 맞춰 잘라 고지하고 최신 질문은 사용자에게 분할을 안내한다. 에이전트 도구 호출/결과 쌍을 보존하는 턴별 trim을 구현한다. 이미지 262토큰·프리필 131 tok/s를 모든 모델의 특성으로 취급하지 않는다.

## R07 — 설정 화면의 일관성

**확인:** `OptionsApp.tsx`는 `loadSettings()`와 최초 `probe(s)`를 별도 effect에서 실행해 저장된 endpoint가 로드되기 전에 기본 주소를 probe할 수 있다. locale을 저장해도 OptionsApp과 main에서 `setLocale`을 호출하지 않는다. MemoryPanel은 설정 사본을 독립적으로 갖고 변경 구독이 없어 기본값 복원 후 표시가 낡을 수 있다. `saveSettings()`는 read-merge-write이므로 빠른 변경과 여러 창의 갱신이 서로 덮어쓸 수 있다.

**개선:** 설정 초기화 완료 후 health 조회, 설정 훅과 onChanged 구독 공통화, 런타임 schema 검증, 입력값 정규화·범위 검사, 저장 직렬화/버전 비교, 오류 상태 및 저장 실패 알림. endpoint는 URL 검증과 로컬/원격 구분, 명시적 권한 획득 흐름을 갖춘다.

## R08 — Ollama 호환성과 실패 처리

- `OptionsApp`는 `/api/tags`의 capabilities만으로 embedding 모델을 필터링한다. 이번 서버는 capabilities를 반환했으나 서버별 차이에 대비해 `/api/show` 보완 조회가 필요하다.
- 연결 확인은 `model-missing`도 연결 성공 문구로 보여줄 수 있다. 서버 연결과 선택 모델 준비 상태를 별도로 표시한다.
- `ollama/client.ts`의 GET/show/embed에는 요청 시간 제한이 없다. health의 HTTP 403은 일반 UNKNOWN으로 처리되어 CORS 안내와 어긋날 수 있다.
- `ollama/stream.ts`의 `consumeLine`은 잘못된 JSON을 버리고 error-only 청크를 별도로 처리하지 않는다. EOF에서 done이 없으면 perf null로 반환할 수 있어 일부 응답이 정상 완료처럼 저장될 여지가 있다.

**개선:** 서버 버전별 contract fixtures, 기능 capability gate(tools/vision/thinking/embedding), 명시적 네트워크 deadline, 스트림 error/done 검증, 불완전 응답 상태와 재시도 UX. malformed NDJSON을 관대하게 처리하더라도 데이터 유실을 사용자에게 숨기지 않는다. 근거 API: [Ollama 모델 목록](https://docs.ollama.com/api/tags), [모델 상세](https://docs.ollama.com/api/show).

## R09 — 데이터 수명과 검색 품질

대화 목록은 최근 50건만 보여주며 전체 검색·페이지 이동·내보내기·복원 UI가 없다. DB에 전체 대화 삭제 함수는 있지만 설정 화면에서 호출하지 않는다. 개별 대화 삭제는 확인/undo 없이 수행된다. 페이지 첨부와 캡처는 이력에 저장하지 않아 과거 대화를 다시 열었을 때 근거가 사라진다.

메모리 만료는 패널 시작 시, 기억 활성화 상태에서만 prune한다. recall/search는 만료 시각을 필터링하지 않는다. 검색은 전체 벡터를 순회하고, `dot()`은 차원이 다르면 짧은 길이에 맞춰 계산한다. 모델 문자열이 같은 다른 차원의 벡터도 명확히 거부하지 않으며 최소 유사도 기준이 없다.

**개선:** 삭제 확인/undo, 대화 검색·내보내기/가져오기·전체 삭제, 근거 메타데이터 보존 정책, 저장 용량·보관 기간 UI. RAG에는 모델 digest·차원 검증, NaN 거부, 임계값과 “근거 없음”, 만료·제외 필터, 재임베딩 경로를 둔다. 규모가 커지면 Worker에서 검색하고 벡터 로딩·처리량을 측정한다.

## R10 — 웹 호환성 및 접근성

`injected.ts`는 요소 탐색 시 화면 가시성·중복·disabled 상태를 검사하지 않고 첫 매치를 선택한다. 입력은 직접 `el.value = ...` 후 이벤트를 보내므로 React controlled input의 상태 변경이 반영되지 않을 수 있다. contenteditable·iframe·Shadow DOM은 별도 처리하지 않는다. 클릭 직후 실제 페이지 결과를 확인하지 않는다.

`ConversationMenu`의 항목은 클릭 가능한 li로 키보드 선택이 부족하다. 승인 카드에는 거부 기본 포커스와 Esc가 있으나 modal focus trap·이전 포커스 복구가 없다. 상태/오류의 스크린리더 알림, 320px 패널, 확대 200%, 고대비·키보드 전용 조작도 확인해야 한다.

**개선:** role/name/label 중심 명확한 요소 식별과 중복 거부, 입력 후 DOM 및 앱 상태 검증, navigation/변경 결과 확인, 테스트용 React 폼·SPA fixture. 대화 선택을 버튼으로 만들고 모달 포커스 관리를 추가한다.

## R11 — 저장소·재현성·출시 준비

**이번 확인:** `.gitignore`에 node_modules가 있어도 **Git 추적 파일 4,100개**가 남아 있다(`git ls-files node_modules`). ignore는 이미 추적된 파일을 해제하지 않는다. `npm ci` 시 설치물이 바뀌면서 불필요한 변경·플랫폼 종속 바이너리 관리 문제가 생길 수 있다.

`package.json`에 engines/packageManager, LICENSE, CI workflow, 브라우저 E2E 설정이 없다. 생성된 manifest에도 minimum_chrome_version이 없다. 기본 live 테스트는 5개 파일에 모델·주소가 하드코딩되고 도구 정확도 실험을 포함해 장시간 소요될 수 있다. lockfile이 있으나 의존성 취약점 없음까지 증명한 것은 아니다.

**개선:** 추적된 의존성은 소유자 검토 후 index에서 제거하고 lockfile로 설치한다(이번 작업에서 제거하지 않음). Node/npm 및 최소 Chrome 버전 선언, clean CI에서 npm ci → compile → test → build → artifact 검증, lockfile 보안 감사, 라이선스·개인정보 고지·배포 버전 정책을 마련한다. 정확도 실험과 짧은 API smoke를 별도 명령으로 분리하고 모델/endpoint 환경 변수화한다.

## R12 — 측정과 유지보수

소스 전반의 “계획서 §N”, “이 머신에서 21초” 등의 주석은 구현 배경을 설명하지만 지속적으로 바뀌는 절 번호와 특정 장비 수치에 결합되어 있다. 일부 한국어 문자열은 번역 카탈로그 밖에 남아 있다. perf의 TTFB는 thinking 첫 토큰도 포함하므로 사용자가 읽을 답변의 첫 토큰 시간과 다르다. 모델/장비 조건이 바뀐 표본을 통합하면 성능 비교도 오해할 수 있다.

**개선:** 고정 아키텍처 결정 문서나 함수 계약으로 주석을 교체한다. TTFT(any/thinking/content), 전체 시간, 모델·컨텍스트·장비·warm/cold를 분리 기록한다. 배포된 기능, 실험 결과, 목표를 구분하고 UI 번역 coverage를 검사한다.
