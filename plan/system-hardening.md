# 시스템 개선 실행 계획

착수: 2026-09-12. 대상: 분석 보고서 R01~R12.

## 실행 순서와 완료 조건

1. 브라우저 작업 안전성(R01~R03): 캡처의 탭/창 확인, 요청 deadline·취소, 승인 대상 일회용 토큰과 문서 검증. 지연·취소·DOM 교체 회귀 테스트.
2. 비동기 데이터 안정성(R04~R05): 기억 삭제와 저장을 DB 트랜잭션으로 직렬화하고 작업 세대로 무효화. 대화/추출/생성 작업 소유권을 검사. 순서가 뒤집힌 응답 테스트.
3. 사용 안정성(R06~R08): 입력 예산 초과 차단, 설정 검증·동기화·저장 직렬화, 모델 기능 조회와 HTTP/스트림 실패 처리. 관련 회귀 테스트.
4. 제품 품질(R09~R12): 기억 검색의 만료/차원 검증, 대화 삭제 확인·키보드 조작, 안전한 입력, 실행 환경/CI 및 문서 현황 갱신.
5. 전체 검사: compile → 단위 테스트 → production build → 가능한 범위의 live smoke. 실제 확장 E2E와 스토어 제출은 별도 검증 상태로 기록.

외부 배포·라이선스 선택·모델 품질 실험은 코드 안정화와 구분한다. 변경 결과와 남은 제품 확장은 이 문서에 갱신한다.

## 다음 작업의 완료 기준

1. **출시 전 브라우저 검증:** [수동 QA](phase5-tool-checklist.md)를 실제 확장·격리 사이트에서 수행하고 Chrome/Ollama/모델·권한·동작 결과를 기록한다. 이미 실행된 클릭의 취소/복구를 약속하지 않는다.
2. **입력·복구 UX:** 자동 축약 시 도구 호출/결과 쌍과 질문을 보존한다. 초과 질문, 오래 걸리는 요청, 저장 실패를 안내하고 재시도할 수 있게 한다.
3. **데이터 관리:** 검색·전체 삭제·백업/복원·근거 보존 정책을 확정하고 잘못된 가져오기 파일·중복·복원 경합을 검증한다.
4. **운영 품질:** 모델 digest·차원 migration, 성능 표본 분리, 번역 coverage와 접근성 QA를 추가한다.
5. **배포:** 원격 CI, 의존성 감사, 소유자가 결정한 라이선스, 개인정보 고지, ZIP·실제 확장 화면을 확인한다. 이번에 커밋·push·스토어 제출은 수행하지 않았다.

근거와 제한은 [개선 보고서](../docs/PROJECT_REVIEW.md), 명령·환경은 [검증 기록](../docs/VALIDATION.md)을 따른다.
