# Phase 5 수동 점검 체크리스트 — 툴 8종

계획서 §9(테스트 전략)의 "수동 · 체크리스트" 항목이다. 자동화된 부분과 사람이
확인해야 하는 부분을 나눠 둔다.

| 항목 | 어디서 검증하나 |
|---|---|
| 툴 스키마 수락 · 인자 검증 | `src/lib/agent/tools.test.ts` (유닛) |
| 루프 종료 조건 · 승인 게이트 | `src/lib/agent/loop.test.ts` (유닛) |
| **도구 선택 정확도 80%** | `src/lib/agent/tools.itest.ts` (`npm run test:live`) |
| **실제 DOM 동작** | ↓ 이 문서 (수동) |

DOM 조작 성공률은 페이지 구조에 좌우되어 자동화해도 의미가 없다. 아래는 실제
확장을 로드해 손으로 확인하는 목록이다.

## 준비

```bash
npm run build
```

`chrome://extensions` → 개발자 모드 → `.output/chrome-mv3` 압축 해제 로드.
설정에서 **에이전트 모드 사용**이 켜져 있는지 확인한다.

## 부작용 없는 도구 (승인 없이 즉시 실행)

| # | 도구 | 시나리오 | 기대 결과 | 확인 |
|---|---|---|---|---|
| 1 | `read_page` | 기사 페이지에서 "이 페이지 요약해줘" | 본문을 읽고 요약. 단계 목록에 `본문 읽기` | ⬜ |
| 2 | `read_page` | 유튜브 영상에서 "무슨 내용이야?" | 자막 기반 응답 | ⬜ |
| 3 | `find_element` | 로그인 있는 사이트에서 "로그인 버튼 있는지 찾아줘" | `찾음: <button> "로그인"` | ⬜ |
| 4 | `find_element` | 없는 요소를 찾게 시킴 | 실패를 그대로 알리고 지어내지 않음 | ⬜ |
| 5 | `list_tabs` | 탭 3개 이상 열고 "열린 탭 알려줘" | 제목·주소 목록, 현재 탭 표시 | ⬜ |
| 6 | `screenshot` | 차트 페이지에서 "화면 보고 설명해줘" | 캡처 후 이미지 기반 설명 (약 5초). ★ 캡처만은 `<all_urls>` 권한이 필요하다(§0.7) — 허용 전에는 권한 안내가 단계 기록에 남고 모델이 다른 방법을 찾아야 정상이다 | ⬜ |
| 7 | `scroll` | "맨 아래로 내려줘" | 실제로 스크롤됨 | ⬜ |
| 8 | `scroll` | "조금만 위로" | 한 화면 위로 이동 | ⬜ |

**여기서 하나라도 승인 없이 실행되면 즉시 중단하고 고친다. 계획서 §7.**

| # | 도구 | 시나리오 | 기대 결과 | 확인 |
|---|---|---|---|---|
| 9 | `click` | "검색 버튼 눌러줘" | 카드에 대상 요소 텍스트·페이지 URL 표시, **거부에 포커스** | ⬜ |
| 10 | `click` | 카드에서 **거부** | 실행되지 않음. 같은 동작을 다시 묻지 않음 | ⬜ |
| 11 | `click` | 카드에서 **승인** | 실행 후 단계에 `승인됨` 배지 | ⬜ |
| 12 | `click` | 승인 카드가 뜬 상태에서 `Esc` | 거부로 처리 | ⬜ |
| 13 | `type_text` | "검색창에 사이드 입력해줘" | 카드에 입력할 문구가 그대로 보임 | ⬜ |
| 14 | `type_text` | 승인 후 | 입력칸에 실제 반영(React 사이트 포함) | ⬜ |
